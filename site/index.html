rustd Install Use Numbers GitHub

A Rust compiler that stays running.

rustd is a daemon that keeps rust-analyzer's analysis of your workspaces in memory and compiled functions on disk. After an edit it compiles the functions that changed and links them into the program rustc already built.

$ cargo rustd run          # first build is cargo's; the daemon loads behind it
$ $EDITOR src/main.rs
$ cargo rustd run          # the daemon compiles what changed, no cargo process runs

cargo and rustc start from the file system on every build. They parse, resolve, type-check and generate code for a whole crate again when one function in it changed, and a second checkout of the same repository starts from nothing. rustd keeps that work. Git worktrees of one repository share one database, and a function compiled once is found again by the hash of what it was compiled from, in any workspace on the machine or, through an S3 bucket, on another machine.

This is a prototype, published for the first time. rustc still does the first build, rustd has no diagnostics and no borrow checker of its own, and it is pinned to Rust 1.99.0. Read the Status section before relying on it.

Install

macOS arm64, Linux x86-64 and Linux AArch64:

curl -fsSL https://raw.githubusercontent.com/DioxusLabs/rustd/main/site/install.sh | sh

Windows x86-64, in PowerShell:

irm https://raw.githubusercontent.com/DioxusLabs/rustd/main/site/install.ps1 | iex

Both download the latest release, check it against the release's SHA-256 sums and put rustd, cargo-rustd and rustd-rustc in ~/.cargo/bin. Set RUSTD_VERSION=nightly for the newest build of main. rustd also needs the toolchain it is pinned to:

rustup toolchain install 1.99.0 --component rust-src

On macOS and Windows the daemon runs and is tested, but cargo rustd does not link programs there yet, so every build is handed to cargo with a line saying so. Linux is where the numbers below come from.

The downloads have the Cranelift backend. The LLVM backend needs LLVM 20 on the machine and is built from source.

Use

There are two ways in. The first is a cargo subcommand, in any project built with 1.99.0:

cargo rustd build
cargo rustd run -- --some-flag
cargo rustd test
cargo rustd check

The second switches it on for plain cargo, for agents and scripts that call cargo themselves. rustd enable adds one key to ~/.cargo/config.toml and rustd disable puts the file back as it was.

rustd enable
cargo run
rustd status
rustd disable

When rustd cannot build something, cargo or rustc builds it and one line on stderr says why. Release builds, other profiles and RUSTFLAGS are handed to cargo unchanged. The cargo guide has the details, and the platform notes say what has been run where.

The first build is not faster than cargo's, because it is cargo's. The plain-cargo mode is currently slower on edits than cargo rustd, and on some projects slower than cargo alone. The full tables, the commit they were measured at and how correctness is checked against rustc are in the results.

What it does not do

  • It does not replace rustc. rustc does the first build and builds everything rustd hands back.
  • It finds no borrow or move errors. cargo rustd check is cargo check.
  • It does not optimise across functions. The code is for the edit loop, not for release.
  • It has been wrong: a fuzzer found twenty-one problems, most of them miscompiles. The ones still open are listed in the support notes.
